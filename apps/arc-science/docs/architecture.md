# Arc Science architecture

Arc Science keeps the previously approved separation between scientific control, multi-model deliberation and scientific visualization. OpenClaw is a replaceable transport/runtime adapter. It never owns research truth or the publication decision.

## Scientific core
The authoritative object is an immutable candidate bound to project, policy, source evidence, producer and exact exported bytes. A typed review may propose changes but cannot issue a numerical or geometry certificate. Missing evidence is unknown, never success. Acceptance here means eligibility for human review; it is not a scientific-validity certificate or submission permission.

## Model execution
Use independent stateless HTTP calls with complete raster-view coverage. A strong model is a model with current task-specific qualification evidence in a trusted registry, not a Boolean supplied by that model. Qualification and cross-model independence still require empirical calibration. There is no shell in model transports.

OpenClaw's compatibility endpoint has operator-level authority; isolate it behind a trusted service boundary. Its store and max_tool_calls fields are not enforcement mechanisms. Explicitly rasterize PDF pages before visual review because text-first PDF extraction can omit figures.

## BioRender
Use the official Streamable HTTP endpoint. Discover tools, validate schemas, and require a pinned schema digest for invocation. Search is allowed for the authorized user's scope. Figure creation requires an action-specific approval and may incur provider credits. This package does not grant asset redistribution rights or transfer this chat's OAuth tokens.

## Visualization
The scene graph keeps structural identity and experimental/predicted status separate from aesthetic parameters. Blender consumes a frozen atomic scene, applies one common coordinate transform and emits a blend file, PNG and render receipt. The first worker draws atoms and explicit C-alpha traces; Molecular Nodes ribbon/surface and trajectory support is the recommended next renderer. It does not invent bonds, contacts, secondary structure, causal arrows or measured activity.

## Vector figures (0.4.0)

An operator imports a completed, authorized SVG/PDF into an immutable asset bundle. The original source, flat proof, converter metadata and provenance determine the asset identity. Verification reads through anchored directories and regenerates proof pixels; unsupported content or incomplete PDF inspection fails the import.

The figure renderer is separate from the atomic worker and from model-selected mission tools. It copies a verified source bundle into a new run, launches a fixed Blender worker in a separate process and retains the job, reservation, log, packed scene, PNG and completion receipt. Studio styling affects framing and the backing panel; the source remains an intact, aspect-correct raster proof. The original vector file remains available separately.

A completed render is a checked workflow result. Its hashes establish consistency among retained files; they do not authenticate rights, replay Blender or establish scientific truth. The [rendering guide](vector-rendering.md) defines the operator workflow and qualified environment.

## Evolution
Route work among versioned harnesses by task family. Change one bounded component at a time using task-level predictions and paired evaluation. Never change active acceptance policy during a run. Development faults may enter repair context; sealed evaluation findings may not. Full durable workflow execution, hosted OAuth callbacks, UI, clinical validation and learned routing are outside this new-core slice.
