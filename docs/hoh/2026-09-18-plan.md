# Loop plan — native startup and truthful research workflows

## Objective

Make the existing local desktop path reliable and evaluate the complete visible
workbench against its real capabilities, including memory and decision routes.

## Scope and ownership

- Leader: persistent HoH setup, source-grounded operating adaptation, interactive
  browser checks, integration, performance observations and final evidence ledger.
- Native planner/developer: `native/arc-desktop` startup/ownership and related docs;
  reuse existing native supervisor code/patterns rather than inventing a second shell.
- Memory assessment/developer: Python memory routes/capture and Memory workspace
  readiness, errors, credential-state lifecycle and meaningful regressions.
- Scientific reviewer: existing usability thesis, citation/novelty audit and narrow
  corrections supported by primary sources.
- Independent QA: frozen candidate review and behavioral checks after implementation.

## Preserve

Prior molecular-render behavior, source hashes, no publication-ready claims, explicit
egress controls, shared in-memory tokens, single service worker per private directory,
existing dependencies and the Rust/Python responsibility boundary.

## Acceptance and evidence

Reproduce observed startup/health/path failures before fixing them; run native
format/test/clippy/release checks. Exercise actual workbench controls via supported
Playwright/browser tools, recording expected/observed results for each product gate.
Probe persisted memory through the UI and source tests without pretending synthetic
embeddings establish semantic quality. Check the scientific thesis against primary
literature and algebraic edge cases; report unsupported novelty as unresolved.

Version accepted loop artifacts and preserve exact test/run boundaries. Do not claim
that a CLI instruction-load check restarts the desktop app. Do not run an unavailable
OMX runtime or adopt new packages as a side effect of workflow configuration.
