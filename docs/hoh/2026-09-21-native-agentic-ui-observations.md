# Native UI observations for the next agentic-product increment

Date: 21 September 2026. Current checkout: `af0529a`. Running window: `native/arc-desktop/target/release/Arc Science.exe`, SHA-256 `833cf5bcb3528d68d806fe8147fb07f577b0fb0043c21dfd8403909460cadec`. This is an inspection of the already-running native WebView, not a fresh cold-start or full functional acceptance run. The window was left open and returned to Diagnostics afterward.

Screenshots were captured from the real EXE window with `PrintWindow` after navigating through its Windows UI Automation controls. They are local, unversioned evidence in `.omx/artifacts/ui-audit-20260921/live-window/`: `diagnostics.png`, `settings.png`, `settings-loaded.png`, `research-live.png`, `prose.png`, `memory.png`, `molecules.png`, `bioart.png`. `research.png` was captured too soon after navigation and is rejected; use `research-live.png`. A native acceptance script initially stopped because the existing window was already on Diagnostics, so its *first-paint* assertion was inapplicable to that existing session. The separate current navigation/captures succeeded. No settings were saved, mission created, provider contacted, or external link opened in this inspection.

| Surface | Direct observation | Product implication / next test |
| --- | --- | --- |
| Settings before loading | Mostly blank editing area, `Not loaded`, `Load settings` and disabled `Save`; no automatic setup summary. | Autoload an authorized snapshot, or give an actionable first-run setup state. Confirm fresh/reused-session behavior. |
| Settings after loading | Five role rows (Planner, Reviewer QA, Falsifier, Vision, Prose) each show Provider `None`, a free-text `model id`, effort `medium`, `API credential`, `file name`, and `inactive / No provider selected`. Footer states in-app provider OAuth is unavailable. | Controls exist, but this is developer-facing plumbing. Require discoverable valid models/auth/effort, pre-save validation, readiness and a usable supported sign-in path. Do not treat a saved field as a live model. |
| Research before a mission | Goal and `Create and start` dominate; `Execution settings · offline fixture (nothing is sent)` is collapsed. No role route, model choices, grants, budgets or claim plan are visible at the decision point. | Show a concise route/permission preview before starting and a detailed session cockpit after start; verify what expanded settings and completed mission already expose before adding duplicates. |
| Diagnostics | Header says `Desktop session ready`, while page says operator session `Not checked`, capabilities load after pasting a token, and MCP/ACP remain `Not checked`. | Align host-session and capability language. A native authenticated user should not be instructed to paste a token merely because a capability probe has not run. Distinguish session, model, connector and release readiness. |
| Prose | Intro and consent explanation fill the left column above actions; local rewrite/diagnosis panels are empty. | Keep protected-span and egress meaning, but make the immediate local action and per-call permission clearer with less front-loaded text. |
| Memory | Search and `Load sessions` are present; right side is empty until a session is selected. | Surface captured agent/session provenance and handoff from a Research run. An empty screenshot does not prove retrieval lacks those details. |
| Molecules | Upload/render form is present, native OS file-picker label is localized in Russian; viewer says choose a file/render. | Preserve the real renderer and viewer while connecting outputs to mission evidence and visualization status. Avoid equating a render with a scientific claim. |
| BioArt | One-use NIH consent is visible; an error says NIH metadata had an unexpected shape, with no selected entry or search result. | Give a structured retrieval receipt, retry/cache path and explicit evidence status; never silently use failed metadata to support a claim. |

Visual judgment: the restrained rail, icon family and legibility are materially improved from the earlier build, but the interface still presents configuration, mission execution, claims and permissions as separate pages. Its most important missing experience is **one inspectable chain from chosen role/model and consent to agent action, evidence, claim scope and release decision**. This is a UI/product finding from the observed states, not a claim that the underlying routes or stored records are absent. Dropdown behavior, live model calls, OAuth, completed mission details, small-screen behavior and the failure page were not tested in this inspection.
