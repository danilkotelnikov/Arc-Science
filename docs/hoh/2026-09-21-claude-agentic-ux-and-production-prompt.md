When a setting is saved, distinguish `saved`, `applied now`, `needs restart`, `not tested`, `failed` and `blocked` in both UI and persistence. Show a reversible path back from a failed test. Confirm stale-revision conflict and restart recovery.

**B. Real model and role selection.** Keep role seats independent: Planner, Reviewer/QA, Falsifier, Vision and Prose, with room for future roles without a hardcoded visual assumption. Offer a usable provider/model picker from a versioned, source-attributed compatibility catalog where official discovery is available; allow an advanced custom model ID only with explicit validation and “unverified” status. Show capability fit (text/vision/tool use/context where obtainable), model identity as actually reported, last probe and actionable readiness; never silently substitute a different model or collapse unsupported effort to another value. Preserve the configured route as a mission snapshot so later settings changes cannot rewrite provenance. Include safe defaults only when they are genuinely compatible and explain how the user can change them. A fully unconfigured row must never look ready just because effort says `medium`.

**C. Supported authentication, not token theatre.** Research the **current official provider contracts** before coding. Treat Claude Code, Codex and Gemini CLI sign-ins as their own account/CLI transports; treat direct Anthropic, OpenAI and Gemini APIs as distinct credentials; implement in-app OAuth only for provider paths that officially support a desktop third-party client. For each provider show exactly which sign-in modes Arc can use now, which require external CLI login, and which are unavailable. Deliver a guided `Connect / Test / Reconnect / Disconnect` flow that works from Settings for supported paths, including cancellation, expired auth, quota/tier failure, revoked credentials and restart. Use native owner-only storage or a supported OS credential broker and explicit loopback/callback validation where applicable; do not copy subscription tokens into API calls or expose secrets to page JavaScript, URLs, storage, logs or artifacts. Do not invent OAuth endpoints or mark account access verified from a saved credential filename. If an official OAuth flow is not offered by a provider, provide the supported CLI or API-key route and state that limitation plainly.
