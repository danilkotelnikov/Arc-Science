## Assumptions stated up front

- **Rust/C++ for management, Python for science.** Process management, configuration,
  launch, settings ownership and the desktop shell move into Rust in this program. The
  numerical, structural and cheminformatics computations stay in Python because that is
  where the scientific libraries live; porting them is a separate multi-month program
  and is recorded as a roadmap, not attempted here. Every loop keeps the Python service
  a replaceable module behind the Rust supervisor.
- **"All structural biology and cheminformatics software"** is delivered as a
  catalogue with availability probes (local Python packages, local executables, the
  Claude Science bench in WSL), not as an installation of every package. The catalogue
  says what is present; it never claims what is not.
- **Humane prose** is delivered as research-cited editorial behaviour (a skill and a
  hook-installable prompt fragment, plus diagnostics in the Prose workspace). Per the
  repository's own editorial rules it does not promise to bypass AI detectors or claim
  that edited text was written without AI, and nothing is taken from commercial
  software's internals.
- **Open items that only the operator can close** (funding the Claude plan, a host
  unreachable through this proxy) are re-attempted where a route exists and otherwise
  stay recorded as blocked with the exact next action.

## Loops, in order

1. **Launch** — `Arc Science.exe` self-configures: finds the sibling supervisor,
   creates and initialises the workspace, discovers Python and the workers, shows a
   window immediately with a starting state, loads the workbench when the service is
   healthy, and shows a native dialog with the reason on failure. Launch logic leaves
   PowerShell for Rust; the `.ps1` becomes a thin developer wrapper.
2. **UI and UX audit** — every workspace inspected in the browser and the native
   window; version mark, duplicated disclaimers, undefined and excess strings removed;
   one short statement where a boundary must be stated.
3. **Settings** — a Rust-owned settings file (`settings.toml` beside the config) with
   validated schema: seats (planner, reviewer/QA, falsifier, vision, prose) → provider,
   model, effort; providers (Claude, OpenAI, Gemini, OpenAI-compatible/OpenClaw,
   standard API key files); OAuth routes through the operator's CLIs (claude, codex,
   gemini); MCP servers; ACP agents; prose detection switch; Blender preset default;
   viewer options. A Settings workspace edits them; the service reloads live where
   safe and marks the rest "restart to apply".
4. **Seats and OAuth** — the `claude-code` CLI transport generalised to `codex exec`
   (ChatGPT subscription) and `gemini -p` (Google OAuth), each tool-less, sandboxed,
   schema-validated, with identity checks and consented probes; standard API adapters
   for OpenAI Responses, Anthropic Messages and Gemini `generateContent`; the OpenClaw
   compatibility endpoint retained; reasoning effort mapped per provider.
5. **MCP and ACP** — an MCP client (stdio and HTTP JSON-RPC: `initialize`,
   `tools/list`, `tools/call`) that exposes configured servers' tools to missions
   under the existing external-connector policy and consent; an ACP client
   (`initialize`, `session/new`, `session/prompt`) that can run a seat through an ACP
   agent such as `gemini --acp`.
6. **Molecular viewer** — Mol* embedded in the Molecules workspace: uploaded
   coordinates render at once; job progress streams as server-sent events; contacts
   and selections update as the calculation produces them; viewer settings
   (representation, colouring, assembly, camera) in the settings space.
7. **Blender presets** — a preset registry (style, palette, lighting, camera,
   resolution, background, outline, depth of field, ambient occlusion, samples)
   exposed by the API and the form; renders record the preset they used.
8. **Molecular catalogue** — a registry of structural-biology and cheminformatics
   tools with probes for local packages, executables and the Claude Science bench;
   a Catalogue view; missions and the viewer consult it.
9. **Humane prose behaviour** — literature-backed (recent detector and stylometry
   work) behaviour delivered as a skill, a hook-installable prompt fragment and
   diagnostics in the Prose workspace.
10. **Open items** — owner-only ACLs on secret files; acceptance files moved out of
    Downloads (recycle bin, not deletion); stale processes; live probes re-attempted
    through every available route; the Claude seat re-probed.
11. **Rust roadmap** — what moved to Rust in this program and the ordered plan for
    the rest, with the boundary each step keeps.
