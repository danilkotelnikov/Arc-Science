# Arc Science recovery execution record

Date: 20 September 2026. Source: [product recovery plan](2026-09-20-product-recovery-plan.md). This record distinguishes the implemented candidate from observed behavior and independent acceptance.

## Increment 1 — Research-first shell and unlock state

**Objective:** Make the first usable action a user-authored Research question, order the primary workspaces Research → Memory → Molecules → BioArt, and make local authorization recoverable without losing unsent input.

**Scope:** Web workbench navigation and Research/Memory authorization UX. The native session boundary is separately designed before any host credential handoff. An ordinary browser retains an explicit unlock path.

**Preserve:** Protected service routes and owner-only token storage, per-mission consent and source provenance, in-memory credential handling, private-data revocation on token change, all other workspaces.

**Acceptance:** An empty cold Research question and opt-in example; ordered accessible navigation at 1280×720 and 700×800; locked, valid, invalid/expired and offline action states; drafts survive credential entry and failure; no raw 401 displayed. Native automatic unlock requires the adversarial tests and boundary conditions in the plan. Browser control observations do not qualify the native WebView by themselves.

**Dependencies:** Compiled web bundle served by the real local service; optional memory worker for session paths; reviewed Wry/WebView2 handoff design before native authentication code.
